void Reportes::canchaConMasReservasActivas(const ColeccionCanchas& coleccionCanchas, const ColeccionReservas& coleccionReservas)

- el propósito de este método es identificar la o las canchas (en caso de empate) con 
la mayor cantidad de reservas en estado activo en el sistema, para ello necesita conocer
por referencia const a la colección de canchas y reservas, ya que estas 2 alojan a los clientes
que a su vez hicieron reservas, con esas reservas se determina a 1 o mas ganadores si es que hay empate.
se usa paso por referencia para no tener que pasar las colecciones enteras ya que son más pesadas, mejor una copia
del objeto en memoria. Al usar const nos aseguramos que solo vamos a leer no modificar.

como sabemos el máximo de reservas por cancha? 
1. Recorrer la lista de 0 a totalCanchas -1 (ya que es un vector)
2. asegurarse de que no haya canchas nulas "nullptr"
3. pedirle a colección de reservas que le devuelva el total de reservas activas
	filtradas por el código de esa cancha.
4. si el conteo es mayor a maxReservas, actualiza la variable maxReservas = conteo.

Filtrar y imprimir
1. recorre nuevamente el arreglo
2. evalúa el conteo de reserva por cancha
3. si el conteo es igual al Max previo, la imprime

-si hay 2 o mas canchas empatadas, va a imprimir todos sin excluir

memoria
1. automática, totalCanchas, maxReservas, conteo
2. dinamico en el puntero Cancha* canchaActual, apunta a memoria que viene de colecciones
no usa new o delete por que es un const que solo lee

validación de apuntadores
1. if canchaActual != nullptr esto previene el fallo por punteros nulos

la lógica es parecida al método anterior, solo que si hay una sentencia de control llamada "continue"
antes el if,  cuando el programa ejecuta un bucle en este caso un for, para recorrer cada cliente para contar las
reservas activas... interrumpe inmediatamente la iteración actual  y salta directamente a la evaluación
de la siguiente iteración, ósea al i++  y la condición de parada del bucle.
posible cambio: anidar el bloque dentro de otro if por ejemplo.
ventajas: si la posición i del arreglo d inamico de clientes contiene un puntero nulo, un hueco de eliminación
o una celda no inicializada-, "continue" impide que el programa invoque:
clienteActual->getIdentificacion(), lo que podría crashear el programa.

diferencias con el de canchas:
1. imprime la info de cada cliente e indica cuantas reservas tiene
2- al mismo tiempo evalúa si el contadorActivas es mayor a el maxReservas, para ir actualizando maxReservas

3- si luego de revisar todos los clientes esa variable maxReservas es igual a 0, se concluye que no hay
reseras activas en todo el programa, imprime el mensaje para avisar y termina con return.

Resolución de empates tiene algo diferente al método de canchas:
4- recorre la colección y, apoyando en el continue para saltar posiciones nulas, filtra e imprime únicamente el cliente o los clientes empatados, cuyos conteos sea igual a maxReservas
